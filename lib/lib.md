# lib/

Data access, rules and helpers for the app. The pure files have no React imports, so Node's test runner can run them directly.

## Subfolders

| Folder | Holds |
| ------ | ----- |
| `account/` | Sign-in session, account state and account labels |
| `api/` | The `Api` interface, mock and Supabase implementations, error types and app config |
| `brief/` | Daily and weekly brief logic |
| `companies/` | Company directory answers, sector grouping, "About: Apple" chips, the company API (Supabase and sample) and batched card tag lookups |
| `feed/` | Feed ordering, paging, ranking (For you, local), swipe and early-request logic (index.html starts the first feed pages, app_config, categories, numbers and feed status before the bundle runs; `earlyFeed.ts` hands them to the api) |
| `following/` | Followed topics and stories, following re-rank |
| `numbers/` | Number formatting, tone and trend sample data |
| `search/` | Search logic |
| `shared/` | Helpers used across folders: app data, card detail, formatting, labels, types, open-URL, card actions |
| `sources/` | Source keys and source info |
| `storage/` | Local preferences and storage wrapper |
| `theme/` | Theme tokens, theme hook and tooltip helper (`webGlobalStyles.ts`: web-only global CSS for focus rings, long-word wrapping and reduced motion) |
| `tutorial/` | Tutorial steps and logic |
| `__tests__/` | Node test-runner tests (`npm run test:app`) |

## Paging, errors and page-hide tracking (review items 3, 4, 9, 11, 12)

- **`feedLogic.ts` – `loadFeedPages`, `decidePage`, `shouldLoadMore`, `needsRefill`.** Paging looks at the list the reader can *see* (hidden topics and sources removed, the same filter the feed screen uses). A page that adds nothing visible keeps fetching, at most `MAX_EMPTY_HOPS` (3) extra pages. The chain always stops when `next_cursor` is null or repeats (any cursor already requested), so it cannot loop; a chain that ends this way marks the feed done. A list that filtered down to nothing while the server has more refills itself (`needsRefill`); an error never refills (retry shows instead). `useFeed(api, query, account, filter)` wires this to React.
- **`errors.ts`.** `friendlyHttpError(status, rawMessage, code)` maps HTTP and PostgREST errors (`invalid_cursor`, `unknown_card`, `PGRST301`, 42501, 4xx/5xx) to short sentences; `userMessage(err, fallback)` shows only our own `ApiError` / `AccountError` text and hides anything else (parse failures, TypeErrors). The raw text stays on the error as `.detail` and is printed with `console.warn` only when `__DEV__` is true. A rejected cursor makes Retry restart the list.
- **`labels.ts` – `feedNoticeText(config)` / `FEED_AI_NOTICE`.** The text of the persistent feed notice strip (D-80): "AI-generated summaries may contain errors · " + the disclaimer (built-in fallback when the config is empty). Tested in `__tests__/disclaimer.test.ts`.
- **`shared/cardBody.ts` – `cardTakeaways`, `cardBarMeta`, `shortTime`.** What a card shows under its headline (2-4 of its own key points, else its summary; link-out cards nothing) and what its bottom bar says (source, document label, time, short time, count, accessible names). Pure; `__tests__/cardBody.test.ts`.
- **`account.ts` – `trackDwellOnExit` and `planRpc`.** The last dwell on `pagehide` is sent with `fetch` `keepalive: true` and the user's auth header (`sendBeacon` cannot set headers). It uses the stored token as it is (nothing can be awaited while the page closes), is skipped when signed out or expired, and never throws.
- New tests: `errors`, `feedPaging`, `disclaimer` (`lib/__tests__/`).

## Seamless feed queue (2026-10-18)

Pages append by card id, so overlap is deduplicated and existing order/keys stay stable. FeedPager reveals additional rows without resetting its offset, pins the visible list position, and has no loading footer while cards are queued. Prefetch targets 3–7 unseen cards. Reranking pins the current and next card (index and index + 1), then ranks farther ahead. Background fetch errors leave queued cards available and retry with capped exponential backoff; an empty feed keeps the normal error/retry state. Tests: `__tests__/queueLogic.test.ts`, `__tests__/pagerLogic.test.ts`.

## Deterministic feed navigation (2026-11-09)

`feed/feedNav.ts` is the pure state machine `components/feed/FeedPager.tsx` runs on. It fixes cards being skipped, the feed jumping back, and cards appearing between the current and the next one.

Why it went wrong before:
- The pager tracked an index, and the list under it kept changing order. At position 0 `app/index.tsx` promotes the tab's head card to the top (`promoteHead`); as soon as the reader moved, the promotion switched off. The old first card slid back to index 1, so it showed again (a backward move), and every later card moved one place.
- The Trending reducer re-runs `diversifyFeed` over the whole list on every new page, so cards already on screen or next in line could swap places, and new-page cards landed in between.
- A like changes the local preferences, which triggers `rerankQueue` with a position taken from `onViewableItemsChanged`. That position lags behind the animated scroll, so cards right after the reader could move.
- `onViewableItemsChanged` fires during the smooth scroll and wrote stale or in-between indexes back as "current". The next arrow press then started from the wrong card.
- Key auto-repeat was not ignored. A held arrow fired many moves and many likes.

The rules now:
- The current card is tracked by id.
- Every rendered card (the `revealed` window, always the current card and at least the next two) keeps its place. Refetches, reranks, head swaps and new pages only change cards not rendered yet, and new cards only join after the frozen ones.
- Hidden cards are dropped. If the current card is hidden, the reader moves forward.
- Each action moves at most one card. `stepNav` and `reactNav` are dropped for `NAV_LOCK_MS` (320 ms) after a move, and the screen ignores `KeyboardEvent.repeat`.
- Like and dislike (arrow key or swipe) act only on the card on screen, then move one card forward.
- Undo goes back to the reacted card (one card back right after a like) and never moves forward.
- Where the list comes to rest (`restingIndex` of the scroll offset, 120 ms after the last scroll event) only moves the reader when it is not a leftover of our own animated move. While a move is pending (`SETTLE_GRACE_MS` 900 ms), reports for other rows are ignored; after that the report wins (the user interrupted).

Tests: `__tests__/feedNav.test.ts` (422 cases: unit cases, 400 seeded fuzz sequences of key presses, auto-repeat, like/dislike/undo, swipes, user and stale scroll reports, refetch reshuffles, inserted cards, reranks and head swaps, plus Drew's case of a held ArrowRight during background refetches), and `e2e/feedNav.spec.ts`.

`feed/toastPlacement.ts` holds the corner Undo toast's position and sizes (phones: bottom 28, over the left end of the card's bottom bar, since cards have no small print any more). `CORNER_TOAST.bottom` (phone 64 px, wide 40 px from the bottom of the area the toast is drawn in) is the single value that sets how high it sits. The pill is 36 px tall and the Undo target is 44 px. `cornerToastText` gives the short visible word and the full spoken sentence. Tests: `__tests__/toastPlacement.test.ts`; the placement itself is checked in `e2e/feedNav.spec.ts`.

Note for code that filters the feed (for example seen-exclusion): removing a card that is already rendered drops it from the pager. If that card is the current one, the reader moves on. Filter new pages, not the cards already on screen.
