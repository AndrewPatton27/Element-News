# scripts/

Build helpers that run outside the app code.

| File | What it does |
| ---- | ------------ |
| `fix-pages-assets.mjs` | Run after `expo export -p web` (see `export:web` in `package.json`). Rewrites the exported asset paths in `dist-pages/` so the static site loads from Cloudflare Pages. Takes the output folder as its only argument: `node scripts/fix-pages-assets.mjs dist-pages`. It also injects into `index.html`: the analytics beacon, the static splash, preloads for the `_layout` and `index` route chunks and the two fonts, the early Supabase fetches (live builds only), and a tiny inline script that preloads the first-run tour chunk (`Tutorial-*.js`) only when `localStorage` has no `element.tutorial-seen.v1` and the path is not `/tutorial` or `/reset-password` (same rules as `lib/tutorial/tutorialLogic.ts`; `scripts/__tests__/tourPreload.test.mjs` keeps them in sync). |
| `gen-companies-sql.mjs` | `node scripts/gen-companies-sql.mjs`. Writes the generated blocks of `supabase/migrations/20261115000000_companies.sql` (company seed from `contract/companies.ts`, CIKs from the SEC ticker fixture) and `supabase/tests/companies_check.sql` (cases from `contract/fixtures/company_tagging_cases.json`). Run it after changing either source; `ingest/test/companies.test.ts` fails while they drift. No network. |
| `gen-companies-extra.mjs` | `node scripts/gen-companies-extra.mjs <path-to-company_tickers_exchange.json>`. Reads `scripts/sec-extra-list.json` (ticker to sector and industry) and SEC's ticker file (download it read-only first, with a descriptive User-Agent), verifies each ticker is on NYSE or Nasdaq, takes the CIK from SEC, drops duplicates, and writes `contract/companiesExtra.ts` and `ingest/src/fixtures/sec-company-tickers-extra.json`. Then run `gen-companies-sql.mjs` (it also writes `supabase/migrations/20261136000000_companies_extra.sql`). |
| `secret-scan.mjs` | Looks for key shapes (JWTs, `sb_secret_`, GitHub tokens, Google and Groq keys, private keys, Healthchecks ping URLs) and for private paths that must never be tracked (`.env`, `CLAUDE.md`, `context/`, `docs/`). `node scripts/secret-scan.mjs --staged` checks the git index before a commit; without the flag it checks every tracked file (CI: `npm run scan:secrets`). Prints file and line, never the value; exit 1 on a finding. |
| `release-check.mjs` | `npm run release:check` (add `-- --e2e` for Playwright). Runs, in order: tsc for app, ingest, functions and worker; `test:app`, `test:ingest`, `test:functions`, `test:worker`, `test:scripts`; the PGlite SQL checks; `cd ml && python -m pytest tests -q`; the secret scan. Prints a PASS / FAIL / SKIP table and exits 1 on any failure. SKIP (with a warning) when Python is absent, `ml/tests` does not exist, or the SQL runner is missing. The runner is `supabase/tests/run-pglite.mjs` (`npm run test:sql`); `RELEASE_SQL_RUNNER` can point at another script. Never prints secret values. |
| `security-headers.mjs` | Builds the Pages `_headers` file (used by `fix-pages-assets.mjs`): HSTS, nosniff, `X-Frame-Options: DENY`, Referrer-Policy, Permissions-Policy, COOP, an enforced CSP that blocks framing (`frame-ancestors 'none'`, `base-uri`, `object-src`, `form-action`), and a report-only full CSP with a sha256 hash for every inline `<script>` in `index.html` plus the Supabase origin. Set `ENFORCE_FULL_CSP = true` once a deploy shows no CSP warnings in the browser console. `public/_headers` is a fallback copy of the same headers. |
| `security-gate.mjs` | Pre-release security gate, read-only (`npm run security:gate`; `npm run release:check -- --prod` runs it with `--require-build`). Checks: no private files tracked, no key shapes in tracked files, no key shapes or server secret values in `dist-pages/` (values read from the environment or `.env`, only names printed), `dist-pages/_headers` security headers and inline-script hashes. `--url <site>` also checks the live headers (one GET); `--db` runs `security-gate.sql` with `npx supabase db query --remote --read-only` and fails if anon or authenticated can execute anything outside the allowlists in the script, if a SECURITY DEFINER function has no pinned search_path, or if a private table or schema is reachable; `--db-json <file>` checks a saved result. Exit 1 on any FAIL. |
| `security-gate.sql` | The read-only catalog query used by `security-gate.mjs --db` (function EXECUTE grants, table privileges and RLS, schema usage). |
| `commit-guard.mjs` | `node scripts/commit-guard.mjs` (a step of `release:check`). Fails when any commit reachable from `HEAD` has an AI `Co-Authored-By` (or "Generated with Claude") line, or tracked source in app, components, lib, ingest, supabase, scripts or contract contains mojibake (UTF-8 read as Windows-1252). `--message <file>` checks one commit message: `.githooks/commit-msg` calls it. Install the hook once per clone with `npm run hooks:install` (sets `core.hooksPath`). |
| `prod-smoke.mjs` | `npm run smoke:prod`. Needs `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` in the environment (public values; never written to files). `SITE_URL` defaults to `https://element-news.pages.dev`. Checks: site returns 200 with the title (`EXPECT_TITLE`, default "Element"); a JS bundle loads; `api.feed` returns cards; the newest card is at most `MAX_AGE_HOURS` old (default 6, 48 on Saturday and Sunday UTC); `api.feed_status()` is not delayed (skipped if absent); every card has an http(s) source link, `app_config.disclaimer` is set, and AI-generated cards carry the AI label. Exit 0 pass, 1 a check failed, 2 missing configuration. |

**Supply (M9).** `supply-readout.mjs` is a read-only card-supply report: `node scripts/supply-readout.mjs [--only a,b] [--print-sql] [--json]`. It runs the queries in `supabase/tests/supply_readout.sql` through `npx supabase db query --remote --read-only`, one single-select request each, and refuses anything that is not a read-only select. `requeue-skipped.sql` is a manual tool that sets report-card-skipped items back to `new` (dry run first, 100 rows per run); see `ingest/ingest.md`. Tests: `scripts/__tests__/supplyReadout.test.mjs`; `npm run test:sql` runs the queries and the requeue on the migrated schema.

Tests: `scripts/__tests__/*.test.mjs` (`npm run test:scripts`, fake fetch and fake runner), `lib/__tests__/fixPagesAssets.test.ts`, `lib/__tests__/secretScan.test.ts`, `scripts/__tests__/securityGate.test.mjs` (headers, bundle scan, grant allowlists).

**Enforcing the full CSP (kept OFF).** The build writes the full policy as `Content-Security-Policy-Report-Only`. To switch it on: (1) `EXPO_PUBLIC_API_MODE=mock npm run export:web`, then `npx playwright test e2e/csp.spec.ts --workers=1` (fails on any violation); (2) deploy the report-only build to production and browse feed, search, brief, a company page, a shared `/b/<id>` link, sign-in and the About page with the browser console open (filter "Content Security Policy" or "Report Only"); leave it up for a few days and check Cloudflare Web Analytics still reports; (3) zero violations: set `ENFORCE_FULL_CSP=1` for the build (`ENFORCE_FULL_CSP=1 npm run export:web`) and set `ENFORCE_FULL_CSP = true` in `lib/share/shareHeaders.ts` (the `/b/<id>` Function keeps its own copy and a test requires both to match); (4) redeploy and repeat the console walk; to roll back rebuild without the variable. `Access-Control-Allow-Origin: *` (a Cloudflare default) is detached for every path with `! Access-Control-Allow-Origin` in `_headers`; the gate fails on a build without it and on a live page that still sends it.
